# ConceptLoom Practice/UI — спецификация фазы 4

Дата: 14 октября 2026. Статус: контракт для планирования и реализации фазы 4.

Основание: [спецификация платформы](2026-10-12-conceptloom-learning-platform-design.md), [Foundation](2026-10-12-conceptloom-foundation.md), [Knowledge](2026-10-13-conceptloom-knowledge.md), [Courses](2026-10-13-conceptloom-courses.md), [план реализации Practice/UI](../plans/2026-10-12-conceptloom-practice.md).

## Цель

Дать учащемуся интерактивные способы применить материал курса — граф знаний, сценарии, симуляции и coding labs — с сохранением ответа, контекста и проверяемого результата. Один и тот же публичный материал упражнения должен быть доступен в поддерживаемом host UI и в понятном текстовом fallback. Приватные критерии оценки остаются на доверенной стороне.

## Результат для пользователя

- Учащийся открывает ограниченный контекстный граф и может перейти от курса или урока к связанным понятиям и источникам.
- Учащийся выполняет сценарий или симуляцию, фиксирует решения и объяснение, а затем отправляет попытку на оценку.
- Ответ и оценка сохраняются как отдельная попытка, связанная с курсом, упражнением и его revision; повторная отправка той же попытки не создаёт второй результат.
- Если host не поддерживает интерактивное представление, пользователь получает текстовый либо локальный HTML fallback и явный способ передать ответ обратно host.
- Coding lab может исполняться только через отдельно настроенный изолированный executor. Если он отсутствует, код можно разобрать без исполнения, а результат явно помечается как непроверенный запуском.

## Область фазы

1. **Контракт упражнения и попытки.** Типизированные публичная постановка, revision, входные файлы и идентификатор. Отдельные приватные критерии и результаты проверки. Публичные tools/resources/UI/export не раскрывают критерии или ожидаемые ответы.
2. **Сохранение и оценка практики.** Отправка ответа, артефактов, использованных подсказок и уверенности. Идемпотентность `attemptId`, конфликт при повторном ID с изменённым содержимым, ссылка на фактический ответ в evidence и сохранение до показа обратной связи.
3. **Представление.** Ограниченное представление графа и урока через host UI/resource, безопасный рендер недоверенных меток и текстовый fallback. Открытие UI не является оценкой или подтверждением mastery.
4. **Сценарии и симуляции.** Разрешённые переходы и наблюдаемые события определены публичным контрактом; скрытая оценка хранится отдельно. Seed позволяет воспроизвести состояние симуляции, а trace сохраняет порядок действий и рассуждение учащегося.
5. **Необязательный coding executor.** Только доверенная команда упражнения, проверенные файлы, ограниченные ресурсы и изолированный backend. Статусы `completed`, `failed`, `timeout`, `unavailable` различаются; `unavailable` и анализ без запуска не являются pass.
6. **Host capability и fallback.** Возможность UI/executor определяется наблюдаемыми capability, а не названием хоста или предположением. Недоступность опциональной интеграции не блокирует сохранение попытки и текстовый сценарий.

## Вне области

- Новая система mastery или обход текущей политики assessment/evidence фазы 1 и course progression фазы 3.
- Автоматическое создание чатов, собственный scheduler или изменение курсового lifecycle.
- Исполнение пользовательского Python/shell внутри обычного MCP процесса, автоматический Docker pull/install, включённая по умолчанию сеть или доступ executor к файловой системе хоста.
- Обещание скрытого ответа в self-check HTML или локальном файле, полностью контролируемом учащимся.
- Полная педагогическая evaluation-платформа, model judges, Promptfoo release gate и доказательство фактического усвоения; это фаза 5.
- Переписывание приложения на React, обязательная установка MCP Apps SDK/Docker, изменение upstream-проектов и интеграция Tracelet.

## Функциональные требования и приёмка

- **PRC-1 — публичный/приватный контракт.** Упражнение имеет стабильный UID и revision. Публичный read/export содержит только постановку и разрешённые стартовые данные. Приватные rubric, expected outputs и скрытые tests отсутствуют в public tool/resource, HTML bundle, starter export и обычном контексте модели. Проверяющий читает критерии только по доверенному пути.
- **PRC-2 — сохранение попытки.** Попытка содержит `attemptId`, exercise UID/revision, фактический ответ и артефакты, а также применимые метаданные (hint/confidence/trace/seed). Сохранённая попытка переживает новый процесс. Повтор одинакового ID и canonical input возвращает прежний receipt; повтор ID с иным input выдаёт конфликт без перезаписи.
- **PRC-3 — оценка и evidence.** Сбор ответа сам по себе не меняет mastery. Каждое заключение assessment связано с точной версией упражнения, действительным ответом и версией rubric; фиксация попытки происходит до feedback. Execution result и оценка рассуждения — различимые типы evidence. Неуспех assessment не стирает уже сохранённый ответ.
- **PRC-4 — интерфейс и безопасный fallback.** UI показывает только разрешённые данные, ограничивает размер графа и корректно отображает недоверенные названия как текст. Неизвестный resource/tool возвращает диагностируемую ошибку. При отсутствии UI есть читаемый fallback с явными шагами отправки/импорта ответа. Отказ UI не теряет упражнение или попытку.
- **PRC-5 — воспроизводимые сценарии.** Недопустимое действие отклоняется без изменения состояния. Одинаковые public spec и seed дают одинаковое начальное состояние/случайные события. Экспорт попытки сохраняет идентификатор и revision упражнения, trace действий и seed; решение не раскрывается до оценки.
- **PRC-6 — ограниченный executor.** Executor не принимает произвольную команду от учащегося; разрешённые входные пути остаются внутри staging directory. Настроенный запуск ограничен временем, памятью, процессами и объёмом вывода; контейнер не имеет сети, root-доступа или записи в host/starter mounts. Приватные тесты не монтируются в среду учащегося. Таймаут и превышение вывода видимы в receipt. При недоступном backend попытка сохраняется со статусом `execution-unverified`/`unavailable`, но не проходит автоматическую проверку.
- **PRC-7 — совместимость.** Новые practice tools/resources не переопределяют существующие имена и сохраняют чистый JSON-RPC transport. Проверка capability отражает фактическое состояние. Без MCP UI или executor остаются доступными допустимые текстовые операции; неподтверждённый host отмечается как непроверенный.

## Общие ограничения

- Node.js `>=20`, ES modules, `node:test`; UI — статический HTML/CSS/JS/SVG, без переписывания приложения.
- Упражнения используют существующие workspace containment/transaction patterns и contracts Foundation, Knowledge и Courses.
- Все public artifacts безопасны для недоверенного текста; HTML не исполняет произвольный HTML из меток или источников.
- Coding executor включается только явной локальной конфигурацией immutable image digest. Никаких сетевых fetch/pull/install во время обычного tool call.
- Фикстуры детерминированы и синтетические. Автоматические тесты не требуют сети, реального host, LLM или Docker daemon; Docker smoke — отдельный optional gate.
- Ручная проверка UI в конкретном host и проверка контейнерной изоляции не выводятся из unit/mock PASS.

## Готовность фазы

PRC-1…PRC-7 покрыты тестами из [плана тестирования](../plans/2026-10-14-conceptloom-practice-test-plan.md). Новые practice, UI и scenario suites, существующие Foundation/Knowledge/Courses regressions, `npm run check` и `npm run verify` проходят на поддерживаемом Node. Ни один P0 тест приватности, целостности попыток, path containment, честного статуса исполнения или transport не пропущен. Host UI, fallback и optional executor имеют отдельные acceptance результаты с указанием фактических проверенных возможностей; недоступная среда перечислена как непроверенная.
